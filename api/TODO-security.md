## Что такое «срок годности» и зачем он

`initData` — строка, которую Telegram выдаёт игре при открытии.
Внутри неё лежит подпись, доказывающая, что данные настоящие.

Проблема: подпись сама по себе не устаревает. Если строку один раз
перехватили — её можно слать на сервер вечно, и он будет верить.

Поэтому внутри есть поле `auth_date` — момент выдачи. Сервер смотрит,
не слишком ли оно старое, и отказывает если да. Украденная строка
перестаёт работать через заданное время.

**Важно:** строка выдаётся один раз при открытии игры и сама не
обновляется. Пока вкладка открыта — она та же. Значит срок годности =
максимальная длина сессии.

## Задача 3 (не сейчас): JWT-сессии

Взрослая схема, стандартная для мини-аппов. Нужна будет, когда появятся
бустеры за реальные звёзды и списание баланса.

Как работает:
1. При старте игра один раз отправляет `initData` на `/api/auth`.
2. Сервер проверяет подпись и выдаёт свой токен (JWT) минут на 15–30.
3. Дальше все запросы ходят с этим токеном, а `initData` по сети
   больше не летает вообще.

Плюсы: у каждого токена короткое окно; сессию можно отозвать;
в токен можно положить свои поля (баланс звёзд, роль игрока).

Минус: это отдельный слой — надо хранить и обновлять токены.
Сейчас у нас три функции без состояния, для игры против ИИ это лишнее.

## Принятый риск (не чинить, пока нет ставок): накрутка `result`

Подпись `initData` защищает `telegram_id`, но не мешает легитимному
пользователю самому вызвать `/api/save-progress` с `{result:'win'}` в
цикле, минуя саму игру, и накрутить себе wins/losses/draws.

Сейчас это ничего не даёт — нет лидербордов и наград, привязанных к
статистике, это просто циферки, которые видит только сам игрок о себе.
Полноценный фикс потребует миграции схемы (например, колонка
`last_result_at` в `users` + серверный кулдаун между засчитанными
матчами) — делать только когда статистика станет на что-то влиять
(рейтинг, награда, публичный лидерборд).

## Принятый риск: нет rate-limiting на API

Ни один из четырёх эндпоинтов не ограничивает частоту запросов —
Vercel-функции без состояния, полноценный rate-limit потребует
отдельного хранилища (например, Upstash Redis). Сейчас цена такой
инфраструктуры не оправдана: `create-invoice` защищён серверным
прайс-листом, `save-progress` теперь ограничивает размер/форму тела
(см. выше). Возвращаться к этому пункту, если появятся признаки
реального злоупотребления или новая платная механика.
